== event_trigger

This sample application is designed to test event rule instance registration
and event triggering via the RuleManager. This SampleComponent registers
"OneShot" and "Property" policy detector instances, and triggers those instances
so that they can be used as event sources for Event Rules (dynamicrules).

Related Interfaces are as follows:

=== Register Rule Instance
Registers a detector instance (OneShot or Property policy) to the RuleManager.

=== Add OneShot Dynamic Rule (Optional)
Adds a camera dynamic rule for the OneShot event exposed by this sample application.
The web page sends the request directly to the camera's `eventrules.cgi`. Since the
OneShot policy represents a pulse event, `State` is not included in the request.

For more information on CGI (SUNAPI), please refer to the link below. +
Link: https://step.hanwhavision.com/en/tech-support?group=d6cf6ed0-4412-4431-a6db-4997fb686859&version=04f2f40b-e45e-48d0-9aea-0f17f119cc8a&file=a8e4589a-95df-4149-8419-6554dbd139e4#4-event-rules

*This feature has been added to improve usability and facilitate understanding.
 The standard workflow is to register it through the web interface.
 Please register it using the following webpage.*

Webpage: [Setup]>[Event]>[Event rule]>[Add]>[Event trigger]>[+Add]>[Channel]>[Event trigger] tab

=== Add Property Dynamic Rule (Optional)
Adds a camera dynamic rule for the Property event exposed by this sample application.
The web page automatically registers the Property instance before sending the CGI
request when it has not been registered yet.

For more information on CGI (SUNAPI), please refer to the link below. +

== Register Rule Instance
=== Register OneShot/Property Instance
Registers a detector instance with "OneShot" or "Property" policy. If the
*Rule Enable* checkbox is checked, the instance is registered with a
dynamic rule option that also creates a matching Rule (Index 1) on the
camera, so that the trigger can be immediately mapped to an Event Rule.

==== Scenario

* Test
[arabic]
. Start the application.
. Click [Go App] in the [Open Platform] menu of the camera web viewer.
. (Optional) Check the *Rule Enable* checkbox under [OneShot] or [Property].
. Click [Send] on the [Register OneShot Rule Instance] or
[Register Property Rule Instance] tab.

* Input Data
+
[options="header"]
|===
|Input data|Type|Description
|enable|bool|Whether to register the instance with a matching Rule option.
|===
** Refer to the RegisterOneShotInstance() / RegisterPropertyInstance()
function in sample_component.cc.

==== Result

* "Pass" is displayed next to the [Register OneShot Rule Instance] or
[Register Property Rule Instance] button.
* To check whether the instance has been registered, follow the path below:
[source,text]
----
Web page: [Setup]>[Event]>[Event rule]>[Add]>[Event trigger]>[+Add]>[Channel]>[Event trigger] tab
----
* Add a registered Event Trigger on that tab.
* (Optional) If the *Rule Enable* checkbox was checked, Select a Rule Index in the tab.
* If the instance is already registered, the request fails and "Fail"
is displayed next to the button.

== Trigger Event
=== Trigger One Shot
Sends a single OneShot trigger for the registered OneShot instance. If
the instance was registered with *Rule Enable*, the rule index is
included so that the trigger is mapped to the Event Rule.

==== Scenario

* Test
[arabic]
. Register the OneShot instance first (see [Register OneShot/Property Instance]).
. (Optional) When registering a Rule Instance, if *Rule Enable* is checked,
the Rule Index is activated.
. (Optional) Set the activated Rule Index to the "Rule Index" selected when 
registering the Instance.
. Click [Send] on the [Trigger One Shot] tab.

* Input Data
+
[options="header"]
|===
|Input data|Type|Description
|(Optional) rule_index|int|Check *Rule Enable* and set the Rule Index that was selected when registering the Rule Instance.
|===
** Refer to the TriggerOneShot() function in sample_component.cc.

==== Result

* "Pass" is displayed next to the [Trigger One Shot] button.
* To check the transmission of trigger events, follow the path below.:
[source,text]
----
Web page: [Setup]>[System]>[Log]>[Event log] tab
----
* Check if the message "Event Rule [Index] Detected" is displayed.


=== Trigger Property
Sends a Property trigger with the selected state for the registered Property instance.
If the instance was registered with *Rule Enable*, the rule index is included so that
the trigger is mapped to the Event Rule.
When registering a Property Instance, if Invert is not checked, the trigger is
activated when the state is "Start", and a trigger must be sent every 5 seconds.
Conversely, if Invert is checked, the trigger is activated when the state is "End",
and it should be sent only once.

==== Scenario

* Test
[arabic]
. Register the Property instance first (see [Register Property Instance]).
. Select the *State* ("Start" or "End") on the [Trigger Property] tab.
. (Optional) When registering a Rule Instance, if *Rule Enable* is checked, the Rule
Index is activated.
. (Optional) Set the activated Rule Index to the "Rule Index" selected when
registering the Instance.
. Click [Send] on the [Trigger Property] tab.

* Input Data
+
[options="header"]
|===
|Input data|Type|Description
|state|string|The Property state to trigger. "Start" or "End". When configuring
an Event Rule on the camera, "Start" corresponds to "Invert" unchecked
and "End" corresponds to "Invert" checked.
|===
** Refer to the TriggerProperty(const std::string& state) function in
sample_component.cc.

==== Result

* "Pass" is displayed next to the [Trigger Property] button.
* The trigger with the selected state is sent, and the same trigger is
repeated every 5 seconds until 15 seconds have elapsed since the request
or a new [Trigger Property] request is sent.
* To check the transmission of trigger events, follow the path below.:
[source,text]
----
Web page: [Setup]>[System]>[Log]>[Event log] tab
----
* Check if the message "Event Rule [Index] Detected" is displayed.
